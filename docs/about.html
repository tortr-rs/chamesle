About

Chamesle is written by one person.

Chamesle is pronounced /tʃa.mes.le/. It's a small project, so things move at that speed.

This is me

I'm the guy who makes Chamesle. 14 years old, sleep deprived, bad at school and a Leicester City fan, so I'm used to things going wrong. Most of this gets written when I should be asleep or doing homework.

If something's broken, that's probably why. Tell me on the board anyway.

Chamesle used to be something else

Until this month, Chamesle was a desktop distro for people leaving Windows, put together from other systems' packages. It had eight desktops, a glass look, a setup program called Jiggity and releases up to 0.7. We dropped all of it on November 14, 2026. It was a lot of work to keep up and not much of it was ours.

The old releases are no longer supported. Nothing from them carries over, and the new system shares no code with them. The old code is still on GitHub if you want to look.

The new one

It starts from the other end: write the small things ourselves and take as little as possible from anyone else.

  • rifle, the coreutils, from scratch, in one C file. It is tested against GNU's tools: 810 cases pass.
    The Rifle Shoots down the GNU
    Unfortunately the GNU herd got so big the rifle doesn't have enough ammo to shoot all of it down.
  • dinit, the init, with Chamesle's own services and boot scripts.
  • mag, the package manager, in one C file with its own inflate, tar, sha256 and RSA. It installs signed binary packages, and builds what no repo has from CRUX, Void and Exherbo source trees.
  • chamesle-bootstrap, which puts the base on a mounted disk with mag, like debootstrap.
  • chamesle-install, which asks a few questions and installs on a whole disk, and the helpers it runs, which work by hand too: chamesle-disk (partitions, and ZFS, btrfs or ext4), chamesle-boot (limine or GRUB).
  • musl for the C library, mksh for the login shell, OpenRC for the init, limine to boot.
  • Linux 6.18 LTS as the kernel, prebuilt. Nobody here builds a kernel.

The rest, the kernel included, comes as binary packages from a large musl repo, which mag reads as it is. Nobody here compiles anything to install Chamesle, so it goes on old machines as fast as on new ones.

Roadmap

Next: more of the base in our own repo, and more machines tested. There are no dates.

X22, our X server, is a separate project and has its own site.

Side project

Chamesle Source is the other end of the same idea: a kernel that starts straight into vi, and nothing else. You write the shell and everything after it.
