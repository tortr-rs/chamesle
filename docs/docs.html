The handbook

How to build and install Chamesle.

The kernel is the only thing in it that comes from outside the Unix family. The C library is musl, the shell is mksh, the packages come from NetBSD's pkgsrc and the package manager is mag.

You put Chamesle on a disk yourself, by hand, in chapter 5. These pages describe the code as it is today. It changes.

1. Getting a root file system

tools/chamesle-bootstrap is to Chamesle what debootstrap is to Debian. It makes the directories and the files in /etc, then builds and installs the base packages into the directory you give it, with mag:

MAG_REPO=$HOME/src/mag/repo:/usr/pkgsrc chamesle-bootstrap /mnt/root

Building everything from source takes a while. LLVM is the long one. Packages are not built twice: the sources are kept in var/cache/mag inside the target.

-s "shells/mksh editors/vim" installs your own list. -n name sets the host name.

The base set has a compiler, lang/clang with devel/lld, lang/compiler-rt and lang/libunwind, so a fresh install builds what you ask of mag by itself. It also has ZFS (sys-fs/zfs and sys-kernel/zfs-module), and gets Chamesle's recipes in /usr/share/mag/repo.

2. mag

mag install editors/vim     fetch, check the checksum, build, install, dependencies first
mag remove vim
mag upgrade                 rebuild what has a newer version
mag search word | info pkg | files pkg | owns /path | deps pkg | list
mag sync                    fetch the pkgsrc tree into /usr/pkgsrc, again to bring it up to date

MAG_REPO is a list of repos split by colons, /usr/share/mag/repo:/usr/pkgsrc if you do not set it. Two kinds of package live in them and can be mixed:

  • our own recipes, category/name, a file with url, sha256, deps and plain sh steps
  • NetBSD pkgsrc packages: a directory with a Makefile, a distinfo and patches/, read without bmake

A file called PROVIDES in a repo says which of our packages stands in for a pkgsrc one, so a pkgsrc package gets our zlib and not a second one. It also lists the dependencies a pkgsrc Makefile forgets (needs). Everything lands in $MAG_ROOT. Nothing is ever installed over a file another package owns, and /etc files you changed stay.

/etc/mag.conf

pkgsrc's mk.conf syntax: plain VAR=value lines, read from $MAG_ROOT/etc/mag.conf.

JOBS=8                          # $JOBS in the steps, make -j
CFLAGS=-O2 -pipe                # also CXXFLAGS, CPPFLAGS, LDFLAGS, for every build
PKG_DEFAULT_OPTIONS=-http2 idn  # options for every pkgsrc package that has them, a minus turns one off
PKG_OPTIONS.vim=python          # the options of one package

mag info net/tnftp shows the options a package ends up with, and its dependencies change with them. Packages of our own repo have no options. They only see JOBS and the flags. Environment wins over the file (MAG_JOBS, CFLAGS).

3. The kernel

Nobody here builds a kernel. sys-kernel/linux is a prebuilt Linux 6.18 LTS kernel and its modules (a generic config, so it runs on nearly any machine). mag fetches it from the binary mirror named in the recipe, checks the checksum and puts vmlinuz, config, System.map and the modules into /boot and /lib/modules.

The mirror drops a package when a newer one comes out, so a new kernel is a new version and sha256 in repo/sys-kernel/linux. The firmware is sys-kernel/linux-firmware.

4. The ISO

The ISO is a live system to install from, nothing more. Chamesle is put on a disk by hand (chapter 5). It boots on BIOS and UEFI machines with limine, from a CD or a stick, and has mksh, vim, mag with our recipes (mag search works before mag sync), chamesle-bootstrap, chamesle-chroot, chamesle-disk, the disk tools (cfdisk, sfdisk, mkfs.ext4, mkfs.fat, zpool, zfs) and this handbook in /usr/share/doc/chamesle/.

iso/mkiso -r $HOME/src/mag/repo:/usr/pkgsrc

What it does, in order:

  1. chamesle-bootstrap builds a root from iso/profile/packages.
  2. The files of iso/profile/overlay, the handbook, mag with its recipes, chamesle-bootstrap, chamesle-chroot and chamesle-disk are copied over it.
  3. mkinitramfs makes the initrd: a few static tools, the modules in iso/profile/modules with what they depend on, and iso/init.
  4. The root becomes a zstd squashfs.
  5. xorriso writes the ISO with limine's BIOS and UEFI boot images.

-R dir uses a root you already have instead of building one. It is copied, not changed.

At boot, init looks for the medium that has LiveOS/rootfs.sfs, mounts it read-only, puts a tmpfs overlay over it and switches into the result. The medium and the squashfs stay mounted under /run/live/.

Try an ISO without a machine:

qemu-system-x86_64 -cpu max -m 1G -cdrom chamesle.iso -boot d
qemu-system-x86_64 -cpu max -m 1G -bios /usr/share/qemu/edk2-x86_64-code.fd -cdrom chamesle.iso   # uefi

mkiso needs mksquashfs (filesystems/squashfs), xorriso (sysutils/libisoburn), zstd, bsdcpio, limine and mag on the machine that builds. LIMINE says where limine's files are (default /usr/share/limine), MAG where mag is.

5. Installing by hand

Boot the ISO, log in as root, bring the network up (dhcpcd) and do this. sda is the disk, change it. chamesle-disk only prepares the disk; the install itself stays by hand.

  1. Partition and format with chamesle-disk /dev/sda. It asks you to type the disk name before it erases anything, then starts cfdisk: make a GPT with a 1M BIOS boot partition, a 512M EFI partition and the rest for /. Then say which partition is the boot partition and which is the root. The boot partition becomes vfat, the root a ZFS pool rpool with the datasets rpool/root, rpool/home and rpool/var. Everything is mounted under /mnt and /mnt/etc/fstab is written: the boot partition by UUID, proc, sysfs, tmpfs, and nothing for ZFS, which mounts its own datasets. limine cannot read ZFS, so the kernel, the initrd and limine.conf are on the vfat partition.
  2. Or do it yourself, for a root on ext4: 
    sfdisk /dev/sda <<P
label: gpt
size=1M, type=21686148-6449-6E6F-744E-656564454649
size=512M, type=U
type=L
P
mkfs.fat -F32 /dev/sda2
mkfs.ext4 /dev/sda3
mount /dev/sda3 /mnt
mkdir /mnt/boot
mount /dev/sda2 /mnt/boot
  3. Put the system in /mnt. Copy the live one, which is quick: 
    tar -C /run/live/rootfs --exclude ./etc/fstab -cf - . | tar -C /mnt -xpf -
[ -e /mnt/etc/fstab ] || cp /run/live/rootfs/etc/fstab /mnt/etc/fstab
cp /run/live/medium/boot/initrd /mnt/boot/initrd
    Or build it from source on a machine with a compiler, with chamesle-bootstrap -n yourhostname /mnt (MAG_REPO set), which takes a while.
  4. Work in the new root with chamesle-chroot /mnt, or run one command there: chamesle-chroot /mnt mag install .... It mounts proc, sys, dev and run, and unmounts them when it ends.
  5. Set the password and the boot entry by hand. blkid gives the UUIDs. With a ZFS root fstab has only the boot line already; with ext4 add the root line. 
    echo 'root:x:0:0:root:/root:/usr/bin/mksh' > /mnt/etc/passwd   # then put a hash in the second field
vim /mnt/etc/fstab
cp /mnt/usr/share/limine/BOOTX64.EFI /mnt/boot/EFI/BOOT/
vim /mnt/boot/limine.conf
    limine.conf: 
    timeout: 3
/Chamesle
    protocol: linux
    path: boot():/vmlinuz-6.18.63-0-lts
    module_path: boot():/initrd
    cmdline: root=UUID=THE-ROOT-UUID rw
    On ZFS the command line is root=ZFS=rpool/root rw.
  6. Install limine for BIOS, unmount and reboot: limine bios-install /dev/sda, umount -R /mnt, and on ZFS zpool export rpool.
  7. On the new system run mag sync, and mag install builds anything from pkgsrc.

The initrd from the ISO finds a root by root=UUID=, root=ZFS= or a device. For anything else, RAID or an encrypted disk, build your own with iso/mkinitramfs.
