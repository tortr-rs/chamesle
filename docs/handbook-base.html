6. The base system

6.1 init

The init is called Winchester. /sbin/init is a mksh script, and it works the way FreeBSD's init does: the kernel starts it as process 1, it runs /etc/rc, then it keeps a getty on every tty and waits for a signal. The files are in files/ in the sources and chamesle-bootstrap copies them into the root. Step by step:

  1. PATH is set to /usr/local/bin:/usr/bin:/bin:/usr/local/sbin:/usr/sbin:/sbin. proc, sysfs and devtmpfs are mounted if they are not yet, and what init prints goes to /dev/console.
  2. If single is on the kernel command line, init runs sulogin first.
  3. /etc/rc autoboot runs (6.2). If it fails, init runs sulogin and goes on when you leave it.
  4. For every name in ttys of init.conf that has a node in /dev, init starts a loop that runs the getty command again whenever it exits. A getty that dies within five seconds is run again after a pause of five.
  5. init waits. A signal ends the wait:
signalwhat it does
INT, TERMreboot
USR1halt: stop everything and stay stopped
USR2power off
  1. Then it runs /etc/rc.shutdown, sends TERM to every process, KILL two seconds later, runs sync, umount -a -r and does the last step through /proc/sysrq-trigger (b or o). That needs CONFIG_MAGIC_SYSRQ in the kernel; the base set has no reboot program of its own that calls the kernel.

6.2 rc, init.conf and the services

/etc/rc mounts the system. In order: / is remounted read-write; with autoboot, fsck -A -R -p checks the other file systems; devpts and /dev/shm are mounted; a tmpfs goes on /run (not on the live ISO, where /run/live is already there); mount -a mounts /etc/fstab; swapon -a; /tmp is emptied if it is not a mount and set to mode 1777; the host name is set; dmesg is saved in /var/log/dmesg.boot. Then every service in boot-services is started, in the order it is written.

/etc/init.conf is the one configuration file. One setting per line, key = value, # starts a comment, blank lines are ignored, spaces around = are free. A list is in braces and may go over several lines:

hostname = chamesle

# started in this order at boot, stopped in reverse at shutdown
boot-services = {udev,modules,network}

modules = {}
ttys = {tty1,tty2,tty3,tty4,tty5,tty6,ttyS0}
getty = agetty --noclear $tty linux
getty-ttyS0 = agetty -L $tty 115200 vt100
keymeaning
hostnamethe host name
boot-servicesthe services started at boot, in order; shutdown stops them in reverse
moduleskernel modules the modules service loads with modprobe
ttysthe ttys that get a getty
gettythe getty command; $tty is the tty name
getty-NAMEthe getty command for that tty alone

The parser is conf in /etc/init.sh; conf KEY prints the value, with a list separated by spaces. A change to ttys or getty takes effect at the next boot.

A service is an executable file in /etc/rc.d (or /usr/local/etc/rc.d, for the ones you add) that takes start, stop, restart or status. The base set has udev (starts udevd, replays the devices and waits for them), modules, network (dhcpcd), and dbus, iwd and NetworkManager for when those packages are installed. A name in boot-services without a script is skipped with one line saying so.

service is the way to run them:

service -l                 every service
service -e                 the services of boot-services, as paths
service network restart
service udev status

To add a service, write the script, make it executable, and put its name in boot-services. With /etc/rc.subr it is short. Set procname to the name the process shows in /proc/PID/comm, write svc_start, and finish with run "$1"; stop then kills that process, status looks for it and start refuses to start it twice. Override svc_stop and svc_status if the defaults do not fit:

#!/bin/sh
. /etc/rc.subr
procname=chronyd
svc_start() { chronyd; }
run "$1"

6.3 Shutting down

reboot, halt and poweroff send INT, USR1 and USR2 to init. shutdown -r, -h or -p does the same, at once (now) or after +minutes, with an optional message sent through wall:

shutdown -r now
shutdown -p +10 back in ten minutes

6.4 The files in /etc

filewhat it holds
passwd, shadow, groupaccounts, password hashes, groups
shellsthe login shells; /bin/mksh is one
init.confhost name, boot services, modules, ttys (6.2)
fstabthe file systems (3.5)
profilePATH, PAGER, umask 022, and /etc/profile.d/*.sh
os-releaseNAME=Chamesle, ID=chamesle
mag/the repos, the keys and the architecture (4.3)
skel/the files new homes start from

The login shell is mksh and /etc/profile is read by login shells. For a prompt and aliases make ~/.mkshrc and set ENV=$HOME/.mkshrc in /etc/profile.

6.5 Users

adduser alice
adduser alice wheel
adduser alice video
adduser alice input

adduser makes the account, the group and the home, and asks for the password; passwd alice changes it. deluser alice takes the account away.

wheel may use doas, which is in the base with permit persist :wheel in /etc/doas.d/wheel.conf. video opens /dev/dri, the graphics, and input the keyboard and mouse under /dev/input. There is no logind to hand them out, so whoever runs X or a Wayland compositor needs both, or Xorg stops with open /dev/dri/card0: Permission denied and no screens found. Groups count from the next login.

6.6 udev and modules

eudev is the udev. udevd gives devices their nodes in /dev and loads the modules the hardware needs.

kmod provides modprobe, insmod, rmmod, lsmod, modinfo and depmod. A kernel's modules are in /lib/modules/VERSION. To load one by hand: modprobe name. To load one at every boot, put its name in modules of /etc/init.conf. To keep one from loading, put blacklist name in a file in /etc/modprobe.d/.

6.7 Networking

dhcpcd is the DHCP client and is in the base set. It is the network service, in boot-services by default, and takes every interface, so a cable is up at boot. ip lists them:

ip addr
ip link set eth0 up

A static address:

ip addr add 192.168.1.10/24 dev eth0
ip route add default via 192.168.1.1
echo 'nameserver 192.168.1.1' > /etc/resolv.conf

and take network out of boot-services.

6.8 Wireless

The card needs its firmware (7.4). Then iwd:

mag install iwd dbus

and put dbus and iwd in boot-services before network:

boot-services = {udev,modules,dbus,iwd,network}

service dbus start, service iwd start to have them now. iwctl connects, the same as on the ISO (2.3), and remembers the network. dhcpcd gives it an address.

wpa_supplicant works too, for those who know it: mag install wpa_supplicant.

6.9 Mounting and disks

mount /dev/sdb1 /mnt/usb
mount -t vfat -o ro /dev/sdb1 /mnt/usb
umount /mnt/usb

mount and umount are busybox's; lsblk, blkid, sfdisk and cfdisk are packages of their own, mkfs.ext4 and fsck.ext4 are e2fsprogs', mkfs.fat is dosfstools', zpool and zfs are zfs.

On a ZFS root, /etc/rc runs zfs mount -a right after mount -a, which mounts rpool/home and rpool/var; the root itself was mounted by the initramfs.
