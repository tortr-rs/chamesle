6. The base system

6.1 init

The init is dinit. /sbin/init is a short script: it mounts proc, sysfs, devtmpfs and /run, and hands over to dinit, which stays process 1. dinit starts the service called boot and everything it needs, keeps the services running, and stops them all in order when the machine goes down. The files are in files/ in the sources and chamesle-bootstrap copies them into the root.

A boot goes:

  1. rootfs: fsck checks the file systems (not with fastboot on the kernel command line), / is remounted read-write, devpts, /dev/shm and the cgroup2 hierarchy are mounted, mount -a mounts /etc/fstab, zfs mount -a mounts the ZFS datasets, swapon -a, and /tmp is emptied. A failed check gives a root shell; leave it to go on.
  2. udevd, then setup: loopback up, the clock, the host name from /etc/hostname, /etc/sysctl.d/*.conf, the modules (6.6), and dmesg into /var/log/dmesg.boot.
  3. udev-trigger replays the devices and waits for them.
  4. Every service in /etc/dinit.d/boot.d, all at once, each after what it depends on.

single on the kernel command line starts a root shell and nothing else; the boot goes on when you leave it. If the boot fails, dinit starts a root shell too.

6.2 Services

A service is a file in /etc/dinit.d named after it. The base set has one for every common daemon, ready for when its package is installed: dbus, elogind, seatd, dhcpcd, iwd, wpa_supplicant, NetworkManager, connmand, lightdm, sddm, gdm, xdm, greetd, sshd, chronyd, ntpd, crond, syslogd, klogd, acpid, cupsd, bluetoothd, avahi-daemon, and the logins tty1 to tty6 and ttyS0. dinitctl does the rest:

dinitctl list                    every service that is loaded, and its state
dinitctl start iwd
dinitctl stop iwd
dinitctl restart dhcpcd
dinitctl status dbus
dinitctl enable NetworkManager   start it now and at every boot
dinitctl disable dhcpcd          not at boot any more

enable and disable make and remove a link in /etc/dinit.d/boot.d; that directory is the list of what starts at boot. A fresh install has dhcpcd and tty1 to tty6 in it. As a user in wheel, dinitctl asks for your password through doas. Where dinit is not running, in arch-chroot /mnt for one, enable and disable still work. service NAME start and the rest still work and run dinitctl.

A service whose process dies is started again, unless it dies over and over in a few seconds; then dinit gives up and dinitctl list shows it stopped. To add a service, write its file. A daemon that can stay in the foreground is a process:

# /etc/dinit.d/chronyd
type = process
command = /usr/sbin/chronyd -d
depends-on = system
smooth-recovery = true

depends-on = system waits for the file systems and devices; depends-on = dbus for the system bus. dinit-service(5) has every setting.

Chamesle before base r18 ran Winchester, a shell init with /etc/init.conf and scripts in /etc/rc.d. The upgrade to r18 moves you over by itself: the host name goes to /etc/hostname, the services of boot-services and the ttys are enabled in dinit (network is dhcpcd now, udev and modules are part of the boot), and init.conf is kept as /etc/init.conf.old. A changed getty line is not carried over; edit /etc/dinit.d/ttyN for that.

6.3 Shutting down

reboot, halt and poweroff ask dinit to stop. It stops the services, the ones others depend on last, sends TERM and then KILL to what is left, turns swap off, unmounts the file systems and powers off. shutdown -r, -h or -p does the same, at once (now) or after +minutes, with an optional message sent through wall:

shutdown -r now
shutdown -p +10 back in ten minutes

6.4 The files in /etc

filewhat it holds
passwd, shadow, groupaccounts, password hashes, groups
shellsthe login shells; /bin/mksh is one
hostnamethe host name
dinit.d/the services, and in boot.d the ones started at boot (6.2)
moduleskernel modules loaded at boot, one a line
fstabthe file systems (3.5)
profilePATH, PAGER, umask 022, and /etc/profile.d/*.sh
os-releaseNAME=Chamesle, ID=chamesle
mag/the repos, the keys and the architecture (4.3)
skel/the files new homes start from

The login shell is mksh and /etc/profile is read by login shells. For a prompt and aliases make ~/.mkshrc and set ENV=$HOME/.mkshrc in /etc/profile.

6.5 Users

adduser alice
adduser alice wheel
adduser alice video
adduser alice input

adduser makes the account, the group and the home, and asks for the password; passwd alice changes it. deluser alice takes the account away.

wheel may use doas, which is in the base with permit persist :wheel in /etc/doas.d/wheel.conf. video opens /dev/dri, the graphics, and input the keyboard and mouse under /dev/input. There is no logind to hand them out, so whoever runs X or a Wayland compositor needs both, or Xorg stops with open /dev/dri/card0: Permission denied and no screens found. Groups count from the next login.

6.6 udev and modules

eudev is the udev. udevd gives devices their nodes in /dev and loads the modules the hardware needs.

kmod provides modprobe, insmod, rmmod, lsmod, modinfo and depmod. A kernel's modules are in /lib/modules/VERSION. To load one by hand: modprobe name. To load one at every boot, put its name on a line of /etc/modules. The base loads the input and network drivers of /usr/lib/modules-load.d/chamesle.conf too. To keep one from loading, put blacklist name in a file in /etc/modprobe.d/.

6.7 Networking

dhcpcd is the DHCP client and is in the base set. It is the dhcpcd service, enabled by default, and takes every interface, so a cable is up at boot. ip lists them:

ip addr
ip link set eth0 up

A static address:

ip addr add 192.168.1.10/24 dev eth0
ip route add default via 192.168.1.1
echo 'nameserver 192.168.1.1' > /etc/resolv.conf

and dinitctl disable dhcpcd.

6.8 Wireless

The card needs its firmware (7.4). Then iwd:

mag install iwd dbus

and enable it, which starts dbus with it:

dinitctl enable iwd

iwctl connects, the same as on the ISO (2.3), and remembers the network. dhcpcd gives it an address.

wpa_supplicant works too, for those who know it: mag install wpa_supplicant.

6.9 Mounting and disks

mount /dev/sdb1 /mnt/usb
mount -t vfat -o ro /dev/sdb1 /mnt/usb
umount /mnt/usb

mount and umount are busybox's; lsblk, blkid, sfdisk and cfdisk are packages of their own, mkfs.ext4 and fsck.ext4 are e2fsprogs', mkfs.fat is dosfstools', zpool and zfs are zfs.

On a ZFS root, the boot runs zfs mount -a right after mount -a, which mounts rpool/home and rpool/var; the root itself was mounted by the initramfs.

6.10 Kernel settings

The boot loads every /etc/sysctl.d/*.conf and /etc/sysctl.conf at boot. The base ships /etc/sysctl.d/10-chamesle.conf: kernel addresses and dmesg are for root only (doas dmesg), a process may ptrace only its own children, users get no BPF, links and files in sticky directories like /tmp are protected, setuid programs leave no core dumps, and the network takes no redirects or source routes and filters spoofed addresses. To change one, put it in a file of your own that sorts later, /etc/sysctl.d/90-local.conf:

kernel.dmesg_restrict = 0

sysctl -a lists them all, sysctl -w name=value changes one until the next boot.
