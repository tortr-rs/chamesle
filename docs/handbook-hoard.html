4. Using hoard

hoard is the package manager of SPAS. It is a replacement for Portage written in Rust, and it runs Gentoo's ebuilds. Chamesle uses Gentoo's repository on the musl profile, so a package is an ebuild in /var/db/repos/gentoo, and everything is built on the machine that installs it, unless a binary package matches.

4.1 The commands

hoard install PKG...       install, dependencies first (-p pretend, -1 do not add to world, -u -D -N, -jN parallel builds)
hoard upgrade              update everything (install -uDN @world)
hoard remove PKG...        uninstall
hoard autoremove           uninstall what @world and @system no longer need
hoard sync                 sync the repositories
hoard search REGEX         names (-d: descriptions too)
hoard info PKG             versions, masks, keywords, USE
hoard list                 what is installed
hoard files PKG            the files a package put on the system
hoard owns PATH            which package a file came from
hoard env-update           regenerate /etc/profile.env and ld.so.conf
hoard manifest PKG|DIR     write the DIST lines of an overlay package's Manifest
hoard self-update          replace a hand-installed hoard with the newest release

A package name works without its category (hoard install tree); hoard asks if two categories have it. hoard --root DIR does any of this in another root, which is how a new system is built (chapter 3).

4.2 Installing and removing

hoard install app-editors/vim
hoard install -p app-misc/fastfetch      what would be built, nothing is done
hoard remove vim

install takes the dependencies first, downloads the sources, checks their size, BLAKE2B and SHA512 against the Manifest, builds in a private directory as the portage user without network, and merges the result. Before it touches anything it checks every file against what other packages own, a file under /etc that you changed stays and the new one is written next to it as ._cfg0000_name, and each file is replaced atomically, so a running program is never half written.

If a build fails, hoard keeps the build directory. hoard install --resume goes on from the phase that stopped, --skipfirst leaves the failed package out and --keep-going builds everything that does not depend on it.

4.3 Where it keeps things

whatwhere
configuration/etc/spas: make.conf, make.profile, repos.conf/, package.use, package.accept_keywords, package.mask, package.license, package.env and env/
the repositories/var/db/repos/gentoo, and any overlay you add
installed packages/var/db/pkg, one directory per package, with its CONTENTS
the world file/var/lib/portage/world
downloaded sources/var/cache/distfiles
binary packagesPKGDIR, from /etc/spas/make.conf

If there is no /etc/spas, hoard reads /etc/portage instead, so a machine that has Portage's files is understood as it is.

4.4 make.conf

/etc/spas/make.conf holds the build settings, in the shell syntax of Portage's:

COMMON_FLAGS="-O2 -pipe -std=gnu17"
CFLAGS="${COMMON_FLAGS}"
CXXFLAGS="${COMMON_FLAGS}"
CHOST="x86_64-pc-linux-musl"
MAKEOPTS="-j8"
ACCEPT_KEYWORDS="amd64"
USE="-systemd"
  • MAKEOPTS is the number of jobs for make, and -jN on the hoard command line is how many packages build at once
  • USE turns features on and off for every package; one package gets its own line in package.use
  • ACCEPT_KEYWORDS says how new the packages may be: amd64 is stable, ~amd64 is testing
  • /etc/spas/make.profile is a link to a profile of the tree. Chamesle uses the musl one: ln -sfn /var/db/repos/gentoo/profiles/default/linux/amd64/23.0/musl /etc/spas/make.profile

-std=gnu17 matters. clang defaults to C23 now, and a lot of older source does not compile under it (section 9.3).

4.5 Repositories

/etc/spas/repos.conf/gentoo.conf names the tree and where it comes from:

[gentoo]
location = /var/db/repos/gentoo
sync-type = git
sync-uri = https://github.com/gentoo-mirror/gentoo.git

hoard sync brings every repository up to date. A git repository whose newest commit is not validly signed is rolled back, and a tree from rsync is checked against its signed Manifests.

4.6 USE flags and keywords

When nothing satisfies a dependency, hoard works out the smallest change that would (a package.use line, a ~amd64 keyword or a license), shows it, and writes it to zz-hoard-autounmask in the config directory after you say yes.

hoard info net-misc/curl                 the versions, the USE flags and what they are now
echo "net-misc/curl http2 -idn" >> /etc/spas/package.use

4.7 Binary packages

hoard install -g uses prebuilt packages from Gentoo's binary host when the version, slot and every USE flag match, and otherwise builds the ebuild. They are checked against the index and the release key before they are unpacked. -b (or FEATURES=buildpkg) saves everything you build as a .gpkg.tar in PKGDIR, and hoard installs from those the next time the version and USE match.

4.8 Writing an ebuild

If the tree does not have what you want, write an ebuild in an overlay. An overlay is a repository with profiles/repo_name, metadata/layout.conf and category/name/name-VERSION.ebuild:

EAPI=8
DESCRIPTION="nl80211 wireless configuration tool"
HOMEPAGE="https://wireless.docs.kernel.org/en/latest/en/users/documentation/iw.html"
SRC_URI="https://cdn.kernel.org/pub/software/network/iw/${P}.tar.xz"
LICENSE="ISC"
SLOT="0"
KEYWORDS="amd64"
DEPEND="dev-libs/libnl"
RDEPEND="${DEPEND}"
BDEPEND="virtual/pkgconfig"

src_install() {
	emake PREFIX="${EPREFIX}/usr" DESTDIR="${D}" install
}

hoard manifest net-wireless/iw writes the checksums of the sources into the package's Manifest. Add the overlay to /etc/spas/repos.conf/, run hoard sync, and hoard install net-wireless/iw builds it.
