3. Installing

The live system has chamesle-install, which asks for the disk, the file system (ZFS, btrfs or ext4), the bootloader (limine or GRUB), the firmware (what the machine has is ticked), wifi, the host name, the root password and a user, and then does this chapter on the whole disk. The log is /var/log/chamesle-install.log, and a copy is kept on the new system. The rest of the chapter is the same install by hand, for another layout or to know what it did.

Follow the BIOS or the UEFI variant where they differ. The disk here is /dev/sda; change it to yours. Everything below is run as root on the live system, and it erases the disk.

There are two ways through 3.1 and 3.2: chamesle-disk does the partitioning and the file systems, or you do both yourself. From 3.3 on the steps are the same, and they are yours: chamesle-disk is only a helper.

3.1 chamesle-disk

chamesle-disk /dev/sda
chamesle-disk -t btrfs /dev/sda
chamesle-disk -t ext4 -y /dev/sda

-t is the file system of the root: zfs (the default), btrfs or ext4. btrfs gets the subvolumes @ for / and @home for /home, mounted with compress=zstd. -y asks nothing and lays out the whole disk as in the table below.

It lists the disk and asks you to type its name before it touches anything. Then it starts cfdisk so you lay out the partitions. Three of them work for BIOS and UEFI both:

partitionsizetypeuse
11MBIOS bootlimine's BIOS code, not used on UEFI
2512MEFI System/boot, FAT32
3the restLinux filesystem/, ZFS

Write the table and quit cfdisk. chamesle-disk lists the partitions and asks which one is the boot partition and which is the root. Then it does, in this order:

mkfs.fat -F32 BOOT
zpool create -f -o ashift=12 -O compression=zstd -O acltype=posixacl -O xattr=sa -O mountpoint=none -R /mnt rpool ROOT
zfs create -o mountpoint=/ -o canmount=noauto rpool/root
zfs mount rpool/root
zfs create -o mountpoint=/home rpool/home
zfs create -o mountpoint=/var rpool/var
zpool set bootfs=rpool/root rpool

and mounts rpool/root, rpool/home and rpool/var under /mnt and the boot partition on /mnt/boot. It also writes /mnt/etc/fstab with the boot partition by UUID and the proc, sysfs and tmpfs lines. It writes nothing else.

ZFS mounts its own datasets, so the fstab does not list them. limine cannot read ZFS: the kernel, the initramfs and limine.conf live on the FAT partition, which is /boot.

ZFS on a machine with little memory is slow; on the 256 MB machine use ext4 (3.2).

3.2 Partitioning and file systems by hand

For a root on ext4. The layout is the one in 3.1, sda1 to sda3:

sfdisk /dev/sda <<P
label: gpt
size=1M, type=21686148-6449-6E6F-744E-656564454649
size=512M, type=U
type=L
P

On an NVMe disk the partitions are /dev/nvme0n1p1 and so on. Replace sda1, sda2 and sda3 throughout.

mkfs.fat -F32 /dev/sda2
mkfs.ext4 /dev/sda3
mount /dev/sda3 /mnt
mkdir /mnt/boot
mount /dev/sda2 /mnt/boot

The FAT partition is /boot. The kernel and limine.conf end up there, where limine looks for them on both BIOS and UEFI.

3.3 chamesle-bootstrap

chamesle-bootstrap /mnt

That is the whole base. It copies /etc/mag/repos and /etc/mag/keys of the live system into /mnt, runs mag update there, and installs chamesle-base, the kernel (linux-lts) and its firmware with everything they need. The kernel package writes vmlinuz-lts and initramfs-lts into /mnt/boot. It takes as long as the download, a few minutes.

chamesle-bootstrap [-a ARCH] [-n HOSTNAME] [-k KERNEL] [-f FIRMWARE] TARGET [PACKAGE]...
optionwhat
-nthe host name, chamesle if not given
-fthe firmware package. The default, linux-firmware-none, has no firmware; take the one your hardware needs (7.4)
-kthe kernel package, linux-lts if not given
-athe architecture, the machine's own if not given (3.10)

Packages after the target go in too. A ThinkPad with Intel wireless and graphics, with an editor:

chamesle-bootstrap -n t480 -f linux-firmware-intel /mnt vim

What chamesle-base brings: OpenRC and the files of chapter 6, mag, rifle, mksh, busybox for the tools rifle does not have, bash, agetty, eudev, kmod, dhcpcd, e2fsprogs, curl and arch-chroot.

3.4 Working inside the new root

arch-chroot /mnt
arch-chroot /mnt passwd root

arch-chroot is Arch's, the same script. It mounts proc, sys, dev, dev/pts, dev/shm, run and tmp under the directory, puts the live system's /etc/resolv.conf in it, and takes the mounts away again when the command ends. Without a command it starts bash. Inside, mag install name works as on the finished system.

3.5 fstab

If you used chamesle-disk the file is written. Look at it: the boot partition by UUID on /boot, then proc, sysfs and tmpfs, and nothing for the ZFS datasets, because ZFS mounts them itself.

By hand, blkid prints the UUIDs:

blkid /dev/sda2 /dev/sda3

Write /mnt/etc/fstab:

UUID=ROOT-UUID  /      ext4   defaults        0 1
UUID=BOOT-UUID  /boot  vfat   defaults        0 2
proc            /proc  proc   defaults        0 0
sysfs           /sys   sysfs  defaults        0 0
tmpfs           /tmp   tmpfs  nosuid,nodev    0 0

A root on ZFS gets no root line.

3.6 Host name and password

The host name is in /mnt/etc/hostname, from -n. Set the root password:

arch-chroot /mnt passwd root

The hash goes into /etc/shadow. The login shell of root is mksh.

3.7 The boot entry

chamesle-boot /mnt
chamesle-boot -b grub /mnt

-b grub installs GRUB instead of limine, for UEFI and for BIOS, and writes /boot/grub/grub.cfg the same way.

It looks at what is mounted on /mnt and /mnt/boot and

  • installs limine into the new root, so its boot files and its limine are the same version
  • for a root on ZFS, installs zfs and zfs-lts, adds zfs to the initramfs (7.5) and zfs-import and zfs-mount to the sysinit runlevel; for btrfs, installs btrfs-progs, adds btrfs to the initramfs and puts the subvolume on the kernel command line
  • writes /mnt/boot/limine.conf with an entry for every kernel in /mnt/boot, the root by UUID, or by dataset on ZFS
  • copies BOOTX64.EFI to EFI/BOOT/ on the boot partition, for UEFI
  • runs limine bios-install on the disk, for BIOS; on a GPT disk only when it has a BIOS boot partition, else it says the disk boots by UEFI only

An old limine.conf is kept as limine.conf.old. If /boot is not FAT, limine cannot read it; chamesle-boot then writes nothing and prints an entry for the GRUB of the system already on the machine (3.11).

What it does by hand follows; skip to 3.8 if it said nothing went wrong.

ls /mnt/boot
System.map-7.3.5-0-lts  config-7.3.5-0-lts  initramfs-lts  vmlinuz-lts

The names stay the same when the kernel is updated, so limine.conf is written once. /mnt/boot/limine.conf, with the UUID of the root partition:

timeout: 3

/Chamesle
    protocol: linux
    path: boot():/vmlinuz-lts
    module_path: boot():/initramfs-lts
    cmdline: root=UUID=ROOT-UUID modules=sd-mod,usb-storage,nvme,ext4 rootfstype=ext4 quiet

boot() is the partition limine.conf is on, which is /boot. The initramfs finds the root, loads the modules on the command line and starts /sbin/init. Take quiet out to see the kernel's messages. For a serial console add console=ttyS0,115200.

A root on ZFS names the dataset; the initramfs needs the zfs module, which is section 7.5:

    cmdline: root=ZFS=rpool/root rootfstype=zfs quiet

Install limine into the new root, and use its files, not the ones of the live system; the two can differ in version, and limine's BIOS stage only works with a limine-bios.sys of its own version:

arch-chroot /mnt mag install limine

BIOS

cp /mnt/usr/share/limine/limine-bios.sys /mnt/boot/
arch-chroot /mnt limine bios-install /dev/sda

limine bios-install writes the loader to the start of the disk and into the BIOS boot partition, which a GPT disk needs (3.1). limine-bios.sys on the FAT partition is the part it loads.

UEFI

mkdir -p /mnt/boot/EFI/BOOT
cp /mnt/usr/share/limine/BOOTX64.EFI /mnt/boot/EFI/BOOT/

The firmware starts EFI/BOOT/BOOTX64.EFI of the EFI System partition by itself.

Do both and the disk boots either way.

3.8 First boot

umount -R /mnt
zpool export rpool
reboot

Leave out zpool export if the root is not on ZFS.

Take out the installation medium. limine shows the entry for three seconds and boots the kernel. OpenRC mounts the file systems, starts the services of the runlevels and puts a login on the ttys. Log in as root. dhcpcd brings up a cable at boot; for wireless see section 6.8.

3.9 What to install next

mag install vim htop tmux
mag search irc

Chapter 4 has the rest, chapter 10 a graphical desktop.

3.10 32-bit machines

On a 32-bit PC (Pentium 4, Athlon XP and the like) boot the ISO on another machine, or install from any Linux there (2.2), and give the architecture:

chamesle-bootstrap -a x86 /mnt

The x86 repository has the same packages, built for i686 with SSE2. -a x86 is written to /mnt/etc/mag/arch, and mag keeps to it from then on. rifle is only built for x86_64, so on x86 busybox gives the coreutils. limine boots 32-bit BIOS machines as well; the entry is the same.

3.11 Next to another system

To keep a Linux that is already on the disk, Chamesle goes on a partition of its own and the other system's GRUB boots both. The other system is not changed, except for one GRUB entry. Make a backup first; shrinking a file system that is in use is not possible, so it is done from the ISO.

Say the disk has an EFI partition nvme0n1p1 and the other system's ext4 root nvme0n1p2, 238G with 100G free. Shrink it to 170G and make the file system fit its partition again:

e2fsck -f /dev/nvme0n1p2
resize2fs /dev/nvme0n1p2 170G
cfdisk /dev/nvme0n1

In cfdisk resize nvme0n1p2 to 171G (a little more than the file system, never less), make nvme0n1p3 in the free space, write and quit. Then

resize2fs /dev/nvme0n1p2
mkfs.ext4 /dev/nvme0n1p3
mount /dev/nvme0n1p3 /mnt

Leave the EFI partition alone and do not mount anything on /mnt/boot: the kernel stays in /boot on the ext4 root, where GRUB reads it. Go on with 3.3 to 3.6. chamesle-boot /mnt then prints a GRUB entry; boot the other system, put the entry at the end of its /etc/grub.d/40_custom and run grub-mkconfig -o /boot/grub/grub.cfg.

To use the same home in both, mount the other root in Chamesle and bind its /home, in /etc/fstab:

UUID=OTHER-ROOT-UUID /old ext4 defaults 0 2
/old/home /home none bind 0 0

and make your user with the same name, user number and group number as there (id on the other system says them):

mkdir /old
addgroup -g 1000 alice
adduser -H -u 1000 -G alice alice

-H makes no home, since the other system's is used: the files, the dotfiles and the settings of the programs are the same in both systems.

3.12 The glibc Chamesle

The install is the same, with -l glibc for chamesle-bootstrap. ZFS is not there: neither Artix nor Arch carries it, so the root is btrfs or ext4.

chamesle-disk -t btrfs -y /dev/sda
chamesle-bootstrap -l glibc -n box -f "linux-firmware-intel linux-firmware-realtek" /mnt networkmanager networkmanager-openrc

The repos and keyrings come from /usr/share/chamesle/glibc on the live system. -k is the kernel (linux, or linux-lts, linux-zen); -f the firmware, split by vendor as in Arch (linux-firmware-amdgpu, -nvidia, -atheros, -broadcom, -mediatek, or linux-firmware for all of it). For an NVIDIA card, add nvidia-open nvidia-utils. Users are made with useradd, services have their names from Artix (NetworkManager, iwd):

echo root:PASSWORD | arch-chroot /mnt chpasswd
arch-chroot /mnt useradd -m -G wheel,video,input,audio alice
arch-chroot /mnt passwd alice
arch-chroot /mnt rc-update del dhcpcd default
arch-chroot /mnt rc-update add NetworkManager default
chamesle-boot /mnt

chamesle-boot sees the glibc system and writes the entries for mkinitcpio's initramfs-linux.img.
