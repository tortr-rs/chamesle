3. Installing by hand

Follow the BIOS or the UEFI variant where they differ. The disk here is /dev/sda; change it to yours. Everything below is run as root on the machine you install from, usually the live ISO, and it erases the disk.

There are two ways through 3.1 and 3.2: chamesle-disk does the partitioning and the file systems and leaves the root on ZFS, or you do both yourself. From 3.3 on the steps are the same, and they are yours: chamesle-disk is only a helper.

3.1 chamesle-disk

chamesle-disk /dev/sda

It lists the disk and asks you to type its name before it touches anything. Then it starts cfdisk so you lay out the partitions. Three of them work for BIOS and UEFI both:

partitionsizetypeuse
11MBIOS bootlimine's BIOS code, not used on UEFI
2512MEFI System/boot, FAT32
3the restLinux filesystem/, ZFS

Write the table and quit cfdisk. chamesle-disk lists the partitions and asks which one is the boot partition and which is the root. Then it does, in this order:

mkfs.fat -F32 BOOT
zpool create -f -o ashift=12 -O compression=zstd -O acltype=posixacl -O xattr=sa -O mountpoint=none -R /mnt rpool ROOT
zfs create -o mountpoint=/ -o canmount=noauto rpool/root
zfs create -o mountpoint=/home rpool/home
zfs create -o mountpoint=/var rpool/var
zpool set bootfs=rpool/root rpool

and mounts rpool/root, rpool/home and rpool/var under /mnt and the boot partition on /mnt/boot. It also writes /mnt/etc/fstab with the boot partition by UUID and the proc, sysfs and tmpfs lines (an existing one is left alone). It writes nothing else: no limine.conf, no host name, no password. Those are 3.7 and 3.8.

ZFS mounts its own datasets, so the fstab does not list them. limine cannot read ZFS: the kernel, the initrd and limine.conf live on the FAT partition, which is /boot, and the initramfs imports the pool (3.8).

3.2 Partitioning and file systems by hand

For a root on ext4. The layout is the one in 3.1, sda1 to sda3:

sfdisk /dev/sda <<P
label: gpt
size=1M, type=21686148-6449-6E6F-744E-656564454649
size=512M, type=U
type=L
P

On an NVMe disk the partitions are /dev/nvme0n1p1 and so on. Replace sda1, sda2 and sda3 throughout.

mkfs.fat -F32 /dev/sda2
mkfs.ext4 /dev/sda3
mount /dev/sda3 /mnt
mkdir /mnt/boot
mount /dev/sda2 /mnt/boot

The FAT partition is /boot. The kernel and limine.conf end up there, where limine looks for them on both BIOS and UEFI. The root can be ZFS by hand as well: the zpool and zfs lines of 3.1 are all there is to it.

3.3 Copying the live system

The live ISO has no compiler, so on a machine booted from it the system is not built, it is copied. The read-only root of the ISO is mounted on /run/live/rootfs and the ISO itself on /run/live/medium:

tar -C /run/live/rootfs --exclude ./etc/fstab -cf - . | tar -C /mnt -xpf -
[ -e /mnt/etc/fstab ] || cp /run/live/rootfs/etc/fstab /mnt/etc/fstab
cp /run/live/medium/boot/initrd /mnt/boot/initrd

That is the whole base system, kernel, modules and ZFS included, as it was when the ISO was made. The copy keeps the fstab chamesle-disk wrote. The firmware for wifi and some network cards is not on the ISO. Add it with hoard once the new system runs (section 4), or build everything instead (3.4), which needs a machine with a compiler.

Work inside the new root with chamesle-chroot:

chamesle-chroot /mnt
chamesle-chroot /mnt passwd root

It mounts proc, sys, dev, dev/pts and a tmpfs on run under the directory, copies /etc/resolv.conf into it, runs chroot with an empty environment (HOME=/root, TERM, PATH) and takes the mounts away again when the command ends. Without a command it starts /usr/bin/mksh -l.

Then go on with 3.6 (fstab) and the rest. rifle (3.5) is on the ISO already, skip it. The kernel is in /mnt/boot already.

3.4 Building the system from source, instead

Have SPAS and the tree ready (sections 2.2 to 2.4) and run chamesle-bootstrap:

$HOME/src/system/tools/chamesle-bootstrap -n yourhostname /mnt

Its usage:

chamesle-bootstrap [-s PACKAGES] [-n HOSTNAME] TARGET
  • -s is the list of packages to install instead of the base set
  • -n is the host name, chamesle if not given

It makes the directories (bin boot dev etc/skel home lib lib/firmware mnt proc root run sbin srv sys tmp usr/bin usr/lib usr/sbin usr/share usr/local/bin var/cache var/lib var/log var/tmp, with tmp and var/tmp mode 1777 and root mode 700), installs everything in files/ (init, rc, the services, init.conf), writes the first /etc files (passwd, group, shells, fstab, profile, os-release, and spas/make.conf with the musl profile), copies the tree into the new root, and builds the base set into the target with hoard --root:

sys-libs/musl app-shells/bash app-shells/mksh sys-apps/util-linux sys-apps/kmod sys-fs/eudev net-misc/dhcpcd
sys-fs/e2fsprogs sys-fs/dosfstools sys-boot/limine sys-kernel/gentoo-sources sys-kernel/linux-firmware
sys-fs/zfs sys-fs/zfs-kmod app-editors/vim llvm-core/clang llvm-core/lld llvm-runtimes/compiler-rt llvm-runtimes/libunwind

llvm-core/clang (with LLVM under it), lld, compiler-rt and libunwind are the compiler of the new system: it builds what hoard install asks for after hoard sync, so no other machine is needed. They are the longest part of the bootstrap. It also installs chamesle-chroot and chamesle-disk, and runs depmod.

The sources go in /mnt/var/cache/distfiles and are not fetched twice. An existing file in /etc is never overwritten, so the script can be run again after a failure. A build that fails stops and names the directory it left behind, and hoard --root /mnt install --resume goes on from where it stopped.

3.5 rifle

The base set has no coreutils: they come from rifle. Install it into the new root:

install -m755 $HOME/src/rifle/rifle /mnt/usr/bin/rifle
$HOME/src/rifle/rifle --install /mnt/usr/bin

rifle --install DIR makes a link for each of its tools in DIR. rifle is built static, so it runs from the host as it is.

Add the packages you want now, or after the first boot:

hoard --root /mnt install app-editors/vim

3.6 fstab

If you used chamesle-disk the file is written. Look at it: the boot partition by UUID on /boot, then proc, sysfs and tmpfs, and nothing for the ZFS datasets, because ZFS mounts them itself.

By hand, blkid prints the UUIDs:

blkid /dev/sda2 /dev/sda3

Open /mnt/etc/fstab and add the root and boot lines under the proc, sysfs and tmpfs lines already there:

UUID=ROOT-UUID  /      ext4  defaults  0 1
UUID=BOOT-UUID  /boot  vfat  defaults  0 2

A root on ZFS gets only the boot line. Check that the UUID is the one blkid shows for the boot partition.

3.7 Host name, users, password

The host name is already in /mnt/etc/init.conf from -n. The root account is in /mnt/etc/passwd with an x in the password field, and there is no shadow file, so the hash goes into that field. Make one on any machine that has openssl, SHA-512:

openssl passwd -6

Put the output in the second field of the root line:

root:$6$salt$hash:0:0:root:/root:/usr/bin/mksh

musl's crypt reads $6$ hashes. An empty field means no password at all.

The groups are root, wheel (10) and users (100). More accounts are lines in passwd and group and a home directory you make (section 6.5).

3.8 The kernel and the boot entry

The kernel package put these in /mnt/boot (the version number is whatever the recipe carries):

ls /mnt/boot
config-6.18.63-0-lts   System.map-6.18.63-0-lts   vmlinuz-6.18.63-0-lts

Write /mnt/boot/limine.conf with the file name you see and the UUID of the root partition:

timeout: 3

/Chamesle
    protocol: linux
    path: boot():/vmlinuz-6.18.63-0-lts
    module_path: boot():/initrd
    cmdline: root=UUID=ROOT-UUID rw console=tty0

For a root on ZFS the command line names the dataset, there is no UUID:

    cmdline: root=ZFS=rpool/root rw console=tty0

boot() is the partition limine.conf is on, which is /boot; with ZFS it is the FAT partition, since limine cannot read ZFS. The kernel has ext4 and the disk drivers as modules, so the system needs the initramfs. The one from the ISO (/mnt/boot/initrd, copied in 3.3) finds the root by root=UUID= or root=ZFS= and loads the modules in iso/profile/modules. Section 7.5 says how to make your own.

limine's files are in /mnt/usr/share/limine.

BIOS

cp /mnt/usr/share/limine/limine-bios.sys /mnt/boot/
limine bios-install /dev/sda

limine bios-install writes the loader to the start of the disk and into the BIOS boot partition. limine-bios.sys on the FAT partition is the part it loads.

UEFI

mkdir -p /mnt/boot/EFI/BOOT
cp /mnt/usr/share/limine/BOOTX64.EFI /mnt/boot/EFI/BOOT/

The firmware starts EFI/BOOT/BOOTX64.EFI of the EFI System partition by itself.

Do both and the disk boots either way.

3.9 First boot

umount -R /mnt
zpool export rpool
reboot

Leave out zpool export if the root is not on ZFS.

Take out the installation medium. limine shows the entry for three seconds and boots the kernel. init runs /etc/rc, which mounts the file systems and starts the services of init.conf, and puts a login on the ttys. Log in as root.

Then:

  1. Bring the network up (section 6.7).
  2. hoard sync brings the Gentoo tree up to date (section 2.3), so hoard install name works from then on, and the compiler is in the base set.
  3. hoard list shows what the bootstrap put on the machine.
