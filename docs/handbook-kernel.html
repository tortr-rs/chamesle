7. The kernel and firmware

7.1 The kernel package

Nobody builds a kernel in Chamesle. sys-kernel/linux is a prebuilt Linux 6.18 LTS kernel with its modules, taken from a binary mirror, with a generic configuration that runs on most machines. The recipe unpacks the package and installs

/boot/vmlinuz-VERSION
/boot/config-VERSION
/boot/System.map-VERSION
/lib/modules/VERSION/

VERSION is the one the package carries, such as 6.18.63-0-lts. sys-kernel/linux-headers has the headers the libc and util-linux build against.

7.2 Updating

The mirror drops a package when a newer one comes out, so a new kernel is a new version and sha256 in the recipe. Edit repo/sys-kernel/linux:

version: 6.18.64
sha256: the new one

The kernel comes from sys-kernel/gentoo-sources, or from sys-kernel/vanilla-sources for the plain one. Install it, which puts the source in /usr/src:

hoard install sys-kernel/gentoo-sources

and add an entry in /boot/limine.conf for the new vmlinuz-VERSION. Keep the old one until the new one has booted:

/Chamesle
    protocol: linux
    path: boot():/vmlinuz-NEW
    cmdline: root=UUID=ROOT-UUID rw

/Chamesle (old)
    protocol: linux
    path: boot():/vmlinuz-OLD
    cmdline: root=UUID=ROOT-UUID rw

After a reboot, uname -r says what runs.

7.3 Modules

Modules are .ko files in /lib/modules/VERSION. lsmod shows what is loaded, modprobe name loads a module with what it needs, modinfo name describes it. udev loads the ones the hardware asks for. Modules belong to one kernel build: after installing a new kernel, reboot before loading any.

7.4 Firmware

hoard install sys-kernel/linux-firmware

puts the firmware for wifi, graphics, ethernet and the rest, compressed with zstd, into /lib/firmware. sys-firmware/sof-firmware has the sound firmware of newer Intel machines. Both are in the base set. A new firmware release is a new version and sha256 in repo/sys-kernel/linux-firmware, the same way as the kernel's.

7.5 An initramfs

A root on ext4 on a common disk (SATA, NVMe, virtio, USB storage) needs none. A root on ZFS needs one: the pool has to be imported before the root can be mounted. A root that needs a module to be reached, or RAID, LVM or an encrypted disk, does.

iso/mkinitramfs makes one, and the live ISO uses it:

mkinitramfs [-m modules-file] ROOTFS KVER OUT

ROOTFS is the root whose /lib/modules and programs are used, KVER the name of the kernel's directory in /lib/modules, OUT the file to write. It puts in a few tools (sh mount umount switch_root insmod mkdir sleep blkid, and zpool when the root has it, with the libraries they need), the modules named in the modules file together with what they depend on, and iso/init. The names after a [zfs] line of the modules file go into a second list, which iso/init loads only for root=ZFS=. The result is a zstd compressed cpio.

$HOME/src/system/iso/mkinitramfs -m modules /mnt 6.18.63-0-lts /mnt/boot/initrd

iso/init mounts proc, sysfs and devtmpfs, loads the modules, reads root= from the command line (root=UUID=... or a device), waits up to 15 seconds for the device, mounts it read-only at /mnt/root, and runs switch_root /mnt/root /sbin/init. With root=ZFS=rpool/root it loads the zfs modules, runs zpool import -N -d /dev rpool (until it works, 15 seconds at most) and mounts the dataset with mount -o zfsutil -t zfs. If anything fails it prints why and drops into a shell.

Name the initrd in limine.conf:

/Chamesle
    protocol: linux
    path: boot():/vmlinuz-6.18.63-0-lts
    module_path: boot():/initrd
    cmdline: root=UUID=ROOT-UUID rw

On ZFS the command line is root=ZFS=rpool/root rw. The ZFS module is sys-kernel/zfs-module, for the kernel of sys-kernel/linux: when one is updated the other has to be too, and depmod has to run after installing it.
