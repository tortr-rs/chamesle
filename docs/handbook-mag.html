4. mag

mag is the package manager. It installs binary packages from the repositories in /etc/mag/repos, checks every index and every package against /etc/mag/keys, and keeps what it installed in /var/lib/mag. It is one C file and runs nothing but the download command.

4.1 The commands

mag update                 get the index of every repo
mag install PKG...         install, with what they need
mag remove PKG...          take packages off
mag upgrade                install what the repos have a newer version of
mag autoremove             remove what was only a dependency and is not needed now
mag list                   what is installed
mag info PKG               version, size, description, and whether it is installed
mag search WORD            names and descriptions
mag files PKG              the files a package put on the system
mag owns PATH              which package a file came from
mag deps PKG               what it needs; rdeps PKG for what needs it
mag fetch PKG...           only download them

-n says what would happen and does nothing, -f goes on when files clash or something still needs a package. MAG_ROOT=/mnt mag ... works on another root, which is what chamesle-bootstrap does.

4.2 Installing and removing

mag install vim
mag -n install xorg-server      what would come with it
mag remove vim

Before it unpacks anything, mag checks each file against what other packages own and stops if two packages want the same file. A file under /etc that you changed stays, and the new one is written next to it as NAME.new. Packages carry scripts that run after they are installed, and triggers that run when a directory they watch changes, like the one that makes the initramfs when a kernel is installed.

A name can also be what a package provides: mag install cmd:htop installs the package that has the command.

4.3 Where it keeps things

whatwhere
the repositories/etc/mag/repos, one URL a line
the keys/etc/mag/keys
the architecture/etc/mag/arch
installed packages/var/lib/mag/NAME/: version, files, deps, explicit and the scripts
indexes and downloads/var/cache/mag

4.4 Repositories

https://chamesle.org/repo
https://dl-cdn.alpinelinux.org/alpine/v3.24/main
https://dl-cdn.alpinelinux.org/alpine/v3.24/community

Each line is the URL above the directory of the architecture: mag adds /x86_64/APKINDEX.tar.gz. A repository you add needs its key in /etc/mag/keys. mag update after any change.

4.5 Making a package

tools/mkapk packs a directory, signs it and leaves its index entry; tools/mkrepo signs the index of a directory of them:

mkapk -k KEY -n hello -v 1.0 -a x86_64 -d "says hello" -D "musl" -o repo/x86_64 ./root
mkrepo repo/x86_64 KEY

Put the public half of KEY in /etc/mag/keys and the repo's URL in /etc/mag/repos. tools/mkpkgs is how Chamesle's own repo is made.
