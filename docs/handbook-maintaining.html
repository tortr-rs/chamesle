9. Maintaining

9.1 Updating packages

hoard sync
hoard upgrade -p
hoard upgrade

sync brings the Gentoo tree up to date (section 2.3), the second says what would be rebuilt, the third rebuilds whatever the tree has a newer version of. One package: hoard install name.

9.2 Cleaning up

hoard autoremove                dependencies nothing needs any more
rm -rf /var/cache/distfiles/*   downloaded sources; they are fetched again when needed

9.3 C23 and CFLAGS

clang compiles C as C23 by default. Older programs written for C89 or C99 stop with errors about bool, true or false used as names, or about functions declared as int f() and called with arguments. CFLAGS="-O2 -std=gnu17" in /etc/spas/make.conf makes the compiler use C17 for every build. It is in the file chamesle-bootstrap writes; if you wrote your own make.conf without it, add it.

To see the error of a failed build, read the log hoard names: the build directory is kept, and hoard install --resume goes on from the phase that stopped.

9.4 Installing into a root

hoard --root /mnt install name builds and merges into /mnt, with the configuration of /mnt/etc/spas. Once the root has musl in it, the builds use the clang of the new root, so a package is built for the system it goes into.

9.5 Build tools

Ebuilds call the usual tools by name: make, awk, sed, grep, diff, cmp, install, python3, perl, m4. The coreutils ones are rifle's, and the rest are packages like any other. A name an ebuild asks for that is missing is a package to install, and hoard install -p says which one.

9.6 Failures you will see

what you seewhy, and what to do
no ebuilds match NAMEthe name is in no repository of repos.conf; try hoard search, and run hoard sync
a checksum mismatchthe download is not the one the Manifest names; hoard fetches it again
no clang in PATHthe build host has no clang outside the new root; install one
files clash, or a package cannot be removedanother package owns the file or needs the package; read what hoard says
errors on bool, true, false or on old declarationsC23; CFLAGS=-O2 -std=gnu17 (section 9.3)
musl's build failsgmake is missing on the host
"root device not found" at bootthe kernel cannot see the disk or the file system: it needs a module, use an initramfs (section 7.5)
the machine boots to a limine promptlimine.conf is not found, or its path: does not name a file in /boot; check with ls /boot
a BIOS machine does not bootlimine bios-install /dev/sda was not run, or limine-bios.sys is not in /boot
a UEFI machine does not bootEFI/BOOT/BOOTX64.EFI is not on the EFI partition, or the partition is not of type EFI System
a login without a passwordthe password field of passwd is empty
no devices in /devudev did not start; check that udevd is installed with hoard list

9.7 Keeping a build

hoard keeps the build directory of a failed build, in /var/tmp/portage. hoard install -f name only downloads and checks the sources, and hoard install --resume carries on from the phase that stopped.
