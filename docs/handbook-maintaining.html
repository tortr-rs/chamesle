9. Maintaining

9.1 Updating

mag update
mag -n upgrade
mag upgrade

The first gets the indexes, the second says what would change, the third does it.

9.2 Cleaning up

mag autoremove                 dependencies nothing needs any more
rm -rf /var/cache/mag/pkg      downloaded packages; they are fetched again when needed

9.3 Configuration files

A changed file under /etc is never written over. When a package brings a new one, it lands next to yours as NAME.new. Look for them after an upgrade and merge by hand:

find /etc -name '*.new'

9.4 Failures you will see

what you seewhy, and what to do
no package NAMEnot in any repo; mag search, and mag update
a signature or hash that does not matchthe download or the index is not what the repo signed; mag update and try again, check /etc/mag/keys
NAME wants FILE, which OTHER hastwo packages want the same file; -f writes over it if you are sure
"root device not found" at bootthe initramfs cannot see the disk or the file system: check root= and modules= in limine.conf
the machine boots to a limine promptlimine.conf is not found, or its path: does not name a file in /boot; check with ls /boot
a BIOS machine does not bootlimine bios-install /dev/sda was not run, or limine-bios.sys is not in /boot
a UEFI machine does not bootEFI/BOOT/BOOTX64.EFI is not on the EFI partition, or the partition is not of type EFI System
no wireless interfacethe firmware is missing (7.4); dmesg names the file
no devices in /devudev did not start; check udev is in boot-services
