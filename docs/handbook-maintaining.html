9. Maintaining

9.1 Updating packages

mag -n upgrade
mag upgrade

The first says what would be rebuilt, the second reinstalls whatever the repos have a newer version of. pkgsrc itself is updated with mag sync (section 2.3). One package: mag install name. When you work with MAG_ROOT set, run mag relocate afterwards.

9.2 Cleaning up

mag autoremove                  dependencies nothing needs any more
rm -rf /var/cache/mag/*         downloaded sources; they are fetched again when needed

9.3 C23 and CFLAGS

clang compiles C as C23 by default. Older programs written for C89 or C99 stop with errors about bool, true or false used as names, or about functions declared as int f() and called with arguments. CFLAGS=-O2 -std=gnu17 in mag.conf makes the compiler use C17 for every build. It is in the file chamesle-bootstrap writes; if you wrote your own mag.conf without it, add it.

To see the error of a failed build, run mag -k install name: the build directory is kept, and the error is above the line that says the steps failed, left in ....

9.4 The root's compiler and mag relocate

When MAG_ROOT has musl in it (usr/lib/crt1.o and usr/lib/libc.so), mag makes a cc script in the build directory and puts it first in PATH, with gcc, clang and c99 as links to it. It runs the clang of the host with --target=x86_64-linux-musl, --sysroot and -isystem pointed at the root, lld, compiler-rt, and the loader and library paths set to the ones in the root, so that what was built runs on the host. -lgcc, -lgcc_s and -lgcc_eh are dropped from the command line because compiler-rt replaces them.

A program built that way names /mnt/usr/lib/libc.so as its loader and /mnt/usr/lib as its library path. On the real system neither exists, and running the program says "not found" although the file is there. mag relocate goes through usr, bin, sbin and lib in the root and puts back /lib/ld-musl-x86_64.so.1 and /usr/lib. Run it before the first boot and after every install into a MAG_ROOT.

If there is no clang in PATH outside the root, mag stops with "no clang in PATH: it is the compiler for a musl root".

9.5 libtool

pkgsrc packages that use libtool expect a libtool script. dev-build/libtool is a small one of Chamesle's that compiles, links and installs shared and static libraries; kmod, for example, is built with LIBTOOL=libtool. If a package fails at a libtool step, read repo/dev-build/libtool/libtool, and for a package that insists on its own libtool pass LIBTOOL=libtool to its make.

9.6 Failures you will see

what you seewhy, and what to do
no recipe for NAMEthe name is in no repo of MAG_REPO; try mag search, and check the pkgsrc path is in MAG_REPO
a checksum mismatchthe download is not the one the recipe names; for the kernel see section 7.2
no clang in PATHthe build host has no clang outside the new root; install one
a program says not found though the file is thereits loader path is the one of the build: MAG_ROOT=... mag relocate
files clash, or a package cannot be removedanother package owns the file or needs the package; read what mag says, -f goes on
errors on bool, true, false or on old declarationsC23; CFLAGS=-O2 -std=gnu17 (section 9.3)
musl's build failsgmake is missing on the host
"root device not found" at bootthe kernel cannot see the disk or the file system: it needs a module, use an initramfs (section 7.5)
the machine boots to a limine promptlimine.conf is not found, or its path: does not name a file in /boot; check with ls /boot
a BIOS machine does not bootlimine bios-install /dev/sda was not run, or limine-bios.sys is not in /boot
a UEFI machine does not bootEFI/BOOT/BOOTX64.EFI is not on the EFI partition, or the partition is not of type EFI System
a login without a passwordthe password field of passwd is empty
no devices in /devudev did not start; check that udevd is installed with mag list

9.7 Keeping a build

mag -k install name

keeps the build directory. mag fetch name downloads and checks the sources without building, and mag build name builds into a staging directory and prints where the files are.
