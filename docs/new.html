November 23, 2026, late: r26

The glibc Chamesle says Chamesle. Artix's packages put their name in os-release, the release files, GRUB's menu and the line OpenRC boots with; the base puts Chamesle back in all of them, and a hook does it again whenever those packages come again. Plasma, fastfetch and the login prompt follow os-release.

The kernel is linux-lts now, as on musl, named 6.18.64-1-lts. To move:

mag update && mag upgrade
mag install linux-lts          # nvidia-open-lts too, for NVIDIA
mag remove linux               # and nvidia-open
chamesle-boot /

mag 0.7.2: mag remove runs pacman's hooks, so a removed kernel leaves /boot as it should. chamesle-boot / works on the running system.

November 23, 2026, later: r25

mag 0.7.1. On the glibc Chamesle a daemon brings its OpenRC service along: mag install lightdm installs lightdm-openrc too, as the musl one always did. It shows in the list before you say yes, and nothing is turned on until rc-update add. What you installed before keeps going without it: mag install foo-openrc once.

November 23, 2026: r24

mag 0.7. It asks now. Before it installs or removes anything it lists the packages, which repo each comes from, what you have now, and how much it downloads and takes on disk:

install (3)
  vim-runtime  9.2.1178-1  extra
  gpm          1.20.7-7    extra
  vim          9.2.1178-1  extra

download 12.3 MiB, installed 40.1 MiB
install? [Y/n]

-y says yes, before or after the command, and MAG_YES=1 does it for a script. Off a terminal it doesn't ask.

It also fetches up to eight packages at once, which on a slow line takes the glibc install down by about half, and the installer leaves the AUR's index for the first mag update on the new system, since the base never comes from there.

The glibc Chamesle shows the logo in fastfetch now.

mag update && mag upgrade brings it. The pacman repos show their sizes after the mag update that follows.

November 22, 2026, late: r23

Two Chamesles now. The installer asks which one.

musl is the one there was, moved to the newest packages: the repos follow the development branch instead of the last stable one, so a fix upstream is a mag upgrade away the same week. The LTS kernel is 7.3.

glibc is new, for what musl can't run: NVIDIA's driver, Steam, anything that only comes built for glibc. It runs on Artix's and Arch's packages, about 25,000, plus the AUR. Same mag, same rifle, same OpenRC, same installer. ZFS isn't there, since neither Artix nor Arch carries it, so the root is btrfs or ext4.

That took mag 0.6. It reads pacman repos as they are: the database, zstd (mag has its own decoder now, still no libc under it), the OpenPGP signatures (RSA and ed25519, against the keyrings the keyring packages install) and the hooks pacman runs after a transaction, which make the initramfs, the users and the caches. A name in two repos comes from the first one, so Artix's OpenRC builds win over Arch's. The AUR is one more repo:

mag install spotify

builds it with makepkg as nobody and installs it like anything else. Read the PKGBUILD first if you don't trust who wrote it; it stays in /var/cache/mag/aur.

Already on Chamesle: mag update && mag upgrade moves you to the new repos. If you changed /etc/mag/repos yourself, the new one is repos.new next to it.

November 22, 2026, night: r22

If your dinit setup had both NetworkManager and wpa_supplicant enabled, the move to OpenRC kept both. The wpa_supplicant service takes the card for itself, and NetworkManager never connects to wifi on its own. r22 turns that service off when NetworkManager is on, since NetworkManager starts its own.

Two things that aren't Chamesle's fault but bite anyone coming from another distro:

  • NetworkManager profiles copied from a system with other interface names (wlp3s0 there, wlan0 here) are tied to that name and never connect. nmcli con modify NAME connection.interface-name "" frees them.
  • The Rescan Wi-Fi button in nmtui is new in NetworkManager 1.58. The repos are on 1.52 for now; until they move, nmcli device wifi rescan before nmtui gives a fresh list.

November 22, 2026, evening: r21

r20 broke the upgrade from r19. The old mag that runs the upgrade doesn't know install_if, so udev's boot scripts and the -openrc service of every daemon stayed out. After the reboot /dev was never set up and every login hit Permission denied on /dev/null. Fresh installs were fine.

r21 puts udev's scripts in the base, and mag 0.5.1 runs once after an upgrade done by an older mag to bring what it left out. If r20 got you, log in as root (that still works) and

mag update && mag upgrade
reboot

Without a network there, chroot in from the ISO and run the same.

November 22, 2026: r20

OpenRC, for good. Winchester and then dinit both worked, but every package in the repos already comes with an OpenRC service, and writing our own for every daemon was a losing game. Now mag install lightdm brings its service with it, and

rc-update add lightdm
rc-service lightdm start
rc-status

is all there is. Upgrading from r18 or r19 moves you over by itself: whatever you had enabled ends up in the default runlevel. Reboot that once with dinit-reboot.

Also in r20:

  • chamesle-install on the ISO: disk, file system, bootloader, firmware, wifi, host name, user, done. The handbook still has the whole install by hand.
  • chamesle-disk -t zfs|btrfs|ext4. btrfs gets @ and @home with zstd.
  • chamesle-boot -b grub next to limine, UEFI and BIOS.
  • mag 0.5: packages that come along by themselves (the -openrc ones), file owners by name so /var/lib/lightdm belongs to lightdm, triggers that fire for subdirectories, and an interrupted run finishes its triggers next time.
  • /etc files you never touched get updated instead of left as .new.

November 21, 2026, late: dinit

Winchester is gone. The init is dinit now, from chamesle-base r18. It keeps the services running and brings back the ones that crash, and turning one on is one command:

dinitctl enable NetworkManager
dinitctl disable dhcpcd
dinitctl list

No reinstall. mag update && mag upgrade and a reboot move you over: the services of your old init.conf get enabled in dinit and the host name goes to /etc/hostname. The base has services for dbus, elogind, gdm, NetworkManager, iwd and wpa_supplicant ready, so GNOME is dinitctl enable gdm away. New ISOs are on the release.

November 21, 2026, at night: mag 0.4 builds from CRUX, Void and Exherbo

Binary packages stay the way in, but some things aren't in any repo. mag 0.4 can now build them from the source trees of three other systems. Add a line to /etc/mag/repos, run mag update, and mag build foo builds the package and installs it:

  • crux https://crux.nu/ports/crux-3.8/opt, with the tree's key in /etc/mag/keys. Every port is checked against its signature before anything runs, and mag has ed25519 for it now.
  • void https://github.com/void-linux/void-packages. Templates run with the helpers of Void's own tree, the way xbps-src runs them, and every source is checked against the template's sha256.
  • exherbo https://gitlab.exherbo.org/exherbo/arbor. Exheres run on a small exheres-0 of mag's own, with the tree's exlibs. Exherbo has no checksums for sources, so those are only as good as the connection.

A package that comes built still wins over all of them, so nothing changes unless you ask for a source build. Handbook 4.6 and 4.7 have the details.

chamesle-base r17 fixes gzip. The base still had gzip, gunzip and python3 links from the days of the stage, pointing at programs that are not there any more. gzip was broken on every install, and python3 could not be installed. mag update && mag upgrade brings both and takes the links away.

November 21, 2026: binary packages, and a bootstrap instead of a stage

Building everything on every machine was too slow, and a Pentium 4 with 256 MB would never get there. So nothing is built any more. mag is back, rewritten as a binary package manager: one C file with its own inflate, tar, sha1, sha256 and RSA, that reads signed apk repos and checks every package before it unpacks it. The big musl repo it reads has about 28,000 packages for x86_64 and as many for 32-bit x86.

The stage is gone too. chamesle-bootstrap /mnt installs the base with mag, like debootstrap, and you write the fstab and the boot entry by hand, as before. Chamesle's own packages, chamesle-base (Winchester and the tools), mag and rifle, are in our repo at chamesle.org/repo.

There is a 32-bit ISO now as well as the x86_64 one. The handbook is rewritten for all of this. SPAS and hoard are retired.

Later the same day: chamesle-boot writes limine.conf from what is mounted on /mnt and puts limine on the disk for UEFI, and for BIOS when the disk has a BIOS boot partition, so the boot entry is no longer written by hand. The base has doas and su works for users. The handbook has a chapter on X with Window Maker and Firefox, and one on installing next to another system. The ISOs are new.

And in the evening, the first install on real hardware, a ThinkPad T480 next to its Gentoo, found the worst bug yet: wireless never worked. A service script is named like its daemon, iwd or NetworkManager, and looked for the daemon by name, found itself, said "already running" and started nothing. Fixed in rc.subr. There is a wpa_supplicant service for NetworkManager now, and chamesle-base r15 hardens the kernel: dmesg and kernel addresses are root's, ptrace only reaches your own children, no BPF for users, the usual protections for links in /tmp, and no ICMP redirects. It is all in /etc/sysctl.d/10-chamesle.conf and handbook 6.10. mag update && mag upgrade brings it.

November 16, 2026: ebuilds, and a name for the init

Packages will come from Gentoo's ebuilds, run by SPAS, instead of pkgsrc and mag. mag could read pkgsrc, but every package that built needed another fix, and we'd rather stand on something that already builds. SPAS now runs on Chamesle, as the hoard command, and reads the Gentoo tree.

rifle has 113 tools now, and more than 1700 test cases against GNU's. It added diff, cmp, pr, fmt, stty, shred, numfmt and the rest of what ebuilds and configure scripts call.

The init is called Winchester.

November 14, 2026: starting over

Chamesle is a new system now. The old one was a Debian-style desktop distro with eight desktops. It was mostly other people's software with our paint on it, and we didn't like where that went. So we stopped, and we're writing the system itself.

What exists today:

  • rifle, the coreutils, in one C file. 87 tools. 810 tests pass against GNU's.
  • mag, the package manager, in one C file. It reads NetBSD pkgsrc natively.
  • An ISO that boots in QEMU on BIOS and UEFI, with musl, mksh, a shell script for init, limine and vim on it.
  • The start of the handbook, which is how you install it, which is how you put it on a disk: by hand.

The plan is on the home page.

The site changed to match. The desktops, the glass look, the apk repo and the package search are gone from it, because none of that is true any more. The 0.8 release will not happen.

X22 is not affected. It has its own site.
